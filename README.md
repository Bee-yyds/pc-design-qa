# PC 端设计验收

给 UI/UX 设计师使用的 Codex Skill。提供 Figma 设计稿和开发页面后，Codex 会核对外观、标注差异，并整理成研发可查看和协作的在线验收报告。

首次使用时，Codex 会在对话中逐步收集信息，检查设计稿和开发页面是否能够读取。你主要提供链接、验收范围和设计判断，配置文件由 Codex 整理。

## 安装

### 使用本地文件夹

将完整的 `pc-design-qa` 文件夹保存到电脑，把它的位置发给 Codex，然后发送下面这段话。

```text
请把我提供的 pc-design-qa 文件夹安装为个人 Skill，检查安装是否成功，然后告诉我怎样开始使用。如果已经安装，请先核对版本和本机修改。
```

### 从 GitHub 安装

从 [GitHub 仓库](https://github.com/Bee-yyds/pc-design-qa) 安装时，可以直接复制以下请求到 Codex。

```text
使用 $skill-installer 从 https://github.com/Bee-yyds/pc-design-qa 安装这个 Skill。请检查安装结果，并告诉我怎样开始第一次验收。
```

Codex 会按当前环境选择安装位置。安装完成后，按它给出的提示调用 Skill。若当前对话尚未识别，可开启新对话再试。

## 第一次使用

复制下面这段话发送给 Codex。

```text
使用 $pc-design-qa。我第一次做 PC 页面设计验收，没有代码基础，请一步步引导我准备。每次问我少量问题，需要我操作时告诉我在哪里操作、完成后怎样继续。
```

如果已有材料，可以直接一起提供。

- 项目、版本和需求名称。
- 本次验收的 Figma 区域链接。
- 开发页面地址。
- 希望检查的模块、页面状态，以及需要排除的内容。

Codex 会继续检查以下条件，并针对缺项给出操作指引。

| 准备事项 | 用途 | 你需要做什么 |
| --- | --- | --- |
| 设计稿连接 | 读取尺寸、颜色、图标和绿色研发说明 | 用自己的账号连接 Figma，并拥有设计文件访问权限 |
| 开发页面连接 | 查看实际外观、读取样式和截图 | 在指定窗口打开页面并登录，完成浏览器连接 |
| 状态样本 | 对照默认、悬停、选中、空态等画面 | 提供已有状态的进入方式，缺少时按提示准备 |
| 在线报告工具 | 保存问题、处理说明、修复状态和修改历史 | 按提示准备 Sites 等必要能力，登录自己的账号 |
| 保存位置 | 保存证据和配置，方便下次接着验收 | 选择当前项目或其他资料目录 |

工具是否可用由 Codex 实际检查。某项连接或权限需要处理时，它会说明受影响的步骤和恢复方式，继续完成其他可独立进行的工作。

登录在你自己的页面完成。密码和验证码交给相应登录界面，验收配置只保存非敏感的项目资料。

## 下次怎样继续

已有配置后，可以直接提出本次任务。

```text
使用 $pc-design-qa，继续这个需求的验收。本次检查顶部菜单的默认和悬停状态，设计稿链接与开发地址如下。请沿用已有报告和配置。
```

复验时提供原问题编号和当前开发地址即可。新需求提供版本、需求名和本轮范围，Codex 会为该需求建立独立报告。

中途暂停后，下次说“继续准备”或“继续验收”，Codex 会读取已保存的进度，只补缺项，并重新检查需要使用的连接。

## 验收与报告

- 默认核对视觉外观，交互按本次明确提出的范围检查。生成预算默认为零，付费动作按明确授权执行。
- 根据设计参数、开发页面实际样式及清晰截图判断差异，保留绿色研发说明要求。
- 一个需求汇总成一份在线报告，模块分批加入。研发可以编辑处理说明和标记修复，设计可以独立标记确认。
- 每条问题有对应截图、红色序号、设计稿位置和可复制的读取提示词。历史记录展示实际变更。
- 无差异结论及本轮尚未完成的事项在对话中反馈，工作进度保存在项目资料内。

首次报告仅你可访问。后续提供协作人员，按授权设置访问。接收者使用自己的账号和设计文件权限。
